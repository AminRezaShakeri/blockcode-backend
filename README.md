# بلوک‌کُد

کتابخانه‌ی فارسی فرمان‌های Minecraft. پروژه دو حالت دارد:

- **GitHub Pages:** حالت نمایشی قبلی، بدون حساب واقعی یا پرداخت.
- **Node.js:** حساب ایمیلی، کیف توکن سروری، تأیید ایمیل و سفارش کارت‌به‌کارت با بررسی دستی.

## اجرای محلی در ویندوز

Node.js نسخه‌ی ۲۲ یا بالاتر را نصب کن. سپس در PowerShell:

```powershell
cd "$HOME\Desktop\MinecraftCodesSite"
Copy-Item .env.example .env
npm.cmd install
npm.cmd start
```

برای اجرای سرور، متغیر `DATABASE_URL` در فایل `.env` باید آدرس PostgreSQL باشد. آدرس اتصال را از پنل Supabase بردار و فقط در `.env` محلی یا تنظیمات محرمانه‌ی هاست قرار بده؛ آن را در GitHub منتشر نکن. `DATABASE_SSL=true` اتصال رمزگذاری‌شده با بررسی گواهی سرور را فعال می‌کند. برای سرویس Render از Shared Pooler در حالت Session استفاده کن؛ آدرس واقعی را از دکمه‌ی Connect پروژه کپی کن. اگر Supabase گواهی CA مخصوص پروژه نشان داد یا TLS خطای گواهی داد، مقدار PEM گواهی را در `DATABASE_SSL_CA` بگذار.

در مرورگر `http://localhost:3000` را باز کن. در حالت توسعه، پیوند تأیید ایمیل در ترمینالی که سرور را اجرا کرده چاپ می‌شود و پس از ثبت‌نام روی صفحه هم نمایش داده می‌شود. این حالت فقط برای توسعه‌ی محلی است.

## ایمیل در هاست

برای ارسال ایمیل واقعی، در تنظیمات محیطی هاست این مقادیر را تنظیم کن:

```text
NODE_ENV=production
APP_URL=https://دامنه-خودت
MAIL_MODE=smtp
SMTP_URL=smtps://نام‌کاربری:رمز@smtp.example.com:465
SMTP_FROM=BlokCode <no-reply@دامنه-خودت>
```

آدرس SMTP و رمز را فقط در تنظیمات محرمانه‌ی هاست وارد کن؛ آن‌ها را در GitHub یا داخل فایل‌های پروژه قرار نده. برای `APP_URL` باید همان نشانی HTTPS باشد که کاربران با آن سایت را باز می‌کنند.

برای دموی کوتاه‌مدت بدون سرویس ایمیل، `MAIL_MODE=console` و `ALLOW_DEVELOPMENT_VERIFICATION_LINKS=true` را تنظیم کن. پیوند تأیید به‌جای ایمیل به همان کاربر نمایش داده می‌شود؛ این تنظیم را برای استفاده‌ی واقعی فعال نگذار.

## کارت‌به‌کارت نیمه‌خودکار

برای نمایش روش کارت‌به‌کارت و ثبت سفارش‌ها در وضعیت انتظار، این متغیرها را در تنظیمات محیطی سرویس Node قرار بده:

```
CARD_TRANSFER_ENABLED=true
CARD_TRANSFER_CARD_NUMBER=شماره-کارت-۱۶-رقمی
CARD_TRANSFER_CARD_HOLDER=نام-دارنده‌ی-کارت
```

شماره‌ی کارت در فایل‌های مخزن ذخیره نمی‌شود، اما وقتی کارت‌به‌کارت فعال باشد، سرور آن را برای نمایش به خریداران در /config.js می‌فرستد؛ بنابراین برای بازدیدکنندگان سایت عمومی است. مقدار کارت را فقط در Environment رندر وارد کن.

فرم سایت راه تماس و چهار رقم آخر کارت مبدأ یا کد پیگیری را ثبت می‌کند و سفارش در جدول public.orders با وضعیت pending می‌ماند. ثبت سفارش به‌تنهایی توکن اضافه نمی‌کند؛ تصویر رسید بارگذاری نمی‌شود و بررسی و تأیید واریز باید دستی انجام شود. برای فعال‌شدن تأیید مدیریتی، یک مقدار تصادفی طولانی و محرمانه در `CARD_TRANSFER_ADMIN_TOKEN` قرار بده. هرگز آن را در GitHub یا چت نفرست.

برای دیدن سفارش‌های در انتظار و تأیید یک‌باره‌ی هر سفارش، از PowerShell استفاده کن؛ مقدار کلید محرمانه را در همان سیستم محلی وارد کن، نه در گفت‌وگو:

```powershell
$env:CARD_TRANSFER_ADMIN_TOKEN = "کلید-محرمانه-خودت"
$headers = @{ Authorization = "Bearer $env:CARD_TRANSFER_ADMIN_TOKEN" }
$orders = Invoke-RestMethod -Headers $headers -Uri "https://blockcode-api.onrender.com/api/admin/card-transfer/orders?status=pending"
$orders.orders
Invoke-RestMethod -Method Post -Headers $headers -Uri "https://blockcode-api.onrender.com/api/admin/card-transfer/orders/شناسه-سفارش/approve"
```

فقط پس از تطبیق واقعی واریز، دستور تأیید را اجرا کن. تأیید موفق سفارش را به `delivered` تغییر می‌دهد و ۱۰ توکن اضافه می‌کند؛ سفارش تأییدشده دوباره قابل‌پرداخت نیست.

## استقرار

GitHub Pages فقط فایل‌های ایستا را اجرا می‌کند و نمی‌تواند `server.js` را اجرا کند. برای حساب واقعی و پرداخت، همین پروژه باید روی هاست Node.js اجرا شود و دامنه به همان سرویس اشاره کند. در تنظیمات سرویس این موارد را انجام بده:

1. دستور نصب: `npm install`
2. دستور اجرا: `npm start`
3. متغیرهای ایمیل و کارت‌به‌کارت بالا را در بخش محیطی سرویس تنظیم کن.
4. متغیرهای محرمانه‌ی `DATABASE_URL`، `DATABASE_SSL=true` و در صورت نیاز `DATABASE_SSL_CA` را در تنظیمات Render قرار بده و سپس سرویس را مستقر کن. برنامه در اولین اجرا جدول‌های موردنیاز را در PostgreSQL می‌سازد.
5. از پایگاه‌داده‌ی Supabase نسخه‌ی پشتیبان بگیر و پیش از راه‌اندازی، اطلاعات دیتابیس قبلی را جداگانه منتقل کن؛ این تغییر ساختار PostgreSQL را می‌سازد و داده‌های SQLite قبلی را خودکار کپی نمی‌کند.

اگر فایل‌های صفحه را همچنان از GitHub Pages باز کنی، حساب و خرید واقعی فعال نمی‌شوند؛ صفحه باید از همان سرویس Node بارگذاری شود تا `/api` و فایل تنظیمات سرور در دسترس باشند.

## نکته‌ی امنیتی

رمزهای عبور با `scrypt` هش می‌شوند، نشست‌ها با کوکی `HttpOnly` نگهداری می‌شوند، و موجودی روزانه، بازشدن راز و تأیید سفارش کارت‌به‌کارت در تراکنش‌های پایگاه‌داده تغییر می‌کند. فعال‌کردن سفارش واقعی به تنظیم امن دامنه‌ی HTTPS، ایمیل و نسخه‌پشتیبان نیاز دارد.
